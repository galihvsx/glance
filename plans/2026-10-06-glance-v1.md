> **For agentic workers:** implement this plan task-by-task. Use the

**Goal:** Build glance v1 — the vertical slice (auth → workspaces/projects → issues → intake triage → board → cycles) as a single Go binary with embedded React SPA, proving the "Plane, but lean" thesis end-to-end.

**Architecture:** Go monolith (Echo) serving `/api/v1/*` JSON, `/ws` websocket hub, and embedded SPA catch-all from one binary. Postgres-only persistence with embedded forward-only migrations. Passwordless auth (email OTP + Google/GitHub OAuth). React+Vite+TS SPA with strict shadcn (Base UI). No plugin runtime.

**Tech Stack:** Go 1.24+ · Echo · pgx v5 (raw SQL, no ORM — N+1 control for perf budgets) · custom minimal migration runner (embedded SQL, ~60 lines, zero new deps) · Postgres 16+ · React 19 + Vite + TypeScript · Tailwind + shadcn (Base UI, all components upfront) · TanStack Query · dnd-kit · TipTap · cmdk · zustand · testify (Go tests)

**Spec:** `~/workspace/glance/spec/2026-10-06-glance-design-spec.md` — the plan argues from the spec; executors read both.

## Global Constraints

- Single binary: `go build ./cmd/glance` must produce a working server (SPA embedded via `go:embed web/dist`).
- Postgres only. No SQLite code paths, no dialect abstraction. Migrations in `migrations/` are forward-only, embedded, auto-run on boot.
- Passwordless: the string `password_hash` must never appear in schema or code. No reset-password flow exists.
- Apache-2.0: `LICENSE` + `NOTICE` at repo root before first public commit.
- shadcn strict: no new UI component where shadcn covers it; no hardcoded color/font tokens — shadcn CSS variables only.
- Naming follows Plane (Intake, Cycle, Module, …). API base `/api/v1/`, project addressed by identifier (`ENG`).
- Every mutation writes an `issue_activities` row. Every async side effect (email, webhook) goes through `outbox`.
- Module path: `glance` (local) until galih creates the GitHub repo, then set the real path before first push. Repo root is `~/workspace/glance/`.
- Commits: one per task, message `feat(scope): …` / `fix(scope): …`.
- Go builds on this VM must use `GOCACHE`/`GOTMPDIR` under the workspace (never `/tmp` — 512M tmpfs).

## Review Focus

1. **OTP abuse** — brute-force codes or spamming someone else's inbox. Expect: 6-digit code, 10-min expiry, ≤5 attempts per code, rate limits (5/hr per email, 20/hr per IP), generic responses that don't reveal whether an email exists.
2. **Sequence counter races** — two concurrent issue creates in one project must never produce duplicate `ENG-123`. Expect: single `UPDATE issue_sequences SET last_value = last_value + 1 … RETURNING` inside the issue-creation transaction.
3. **N+1 on issue lists** — board/list with assignees+labels must not fan out per row. Expect: one query with joins/aggregates (or explicit dataloader), covered by a query-count test.
4. **`sort_order` float exhaustion** — repeated drag-drops between the same two cards must not collapse precision. Expect: rebalance routine + test that inserts 50 midpoints then rebalances.
5. **WS auth bypass** — unauthenticated clients must never receive events. Expect: cookie session or single-use expiring ticket required before any subscribe; test connects without auth and gets rejected.

## Deferred tables (ship with their feature plans, post-v1)

`pages`, `issue_views`, `attachments`, `favorites` (+ module UI, gantt, calendar, roadmaps, analytics, spreadsheet, public boards, admin panel) are intentionally absent from v1 migrations. Each post-v1 feature plan adds its own forward-only migration — no big-bang schema.
