Epics UI

Static HTML spec for the cycle-71 frontend task. The backend is already on main (C71T0, commit 3a1afdb). Each surface below carries a blue spec-note with the exact contract the React implementation must honor. Nothing here is the app — it is the visual + behavioral spec the coordinator reviews before implementation.

Surface 1 — Epics list (project scope). Contract:
  • GET /api/v1/workspaces/:slug/projects/:identifier/epics → {epics: [{id, name, description, archived_at, issue_count, created_at}]}. Archived epics are excluded by the server unless ?include_archived=true — the toggle re-issues the list query with that flag.
  • Row carries: name, description snippet (line-clamp-2), issue_count, and the stacked state-group progress bar. The list endpoint ships no progress — each card fetches GET /epics/:epicID for progress.by_group (mirrors the Initiatives list × rollup pattern), or the list query may embed it — implementer’s call, keep per-card skeleton.
  • Archived badge = OrgStatusChip muted (#777780) labeled Archived; archived cards dim to 55% opacity.
  • Out of scope this cycle: group-by-epic in list/board/calendar layouts, duplicate-epic across projects, start/target dates (per cycle71-plan.md).

Surface 2 — Epic detail. Contract:
  • GET /epics/:epicID → {epic, progress: {total, by_group}, issue_count}. by_group uses the API vocabulary backlog | unstarted | started | completed | cancelled; colors mirror GROUP_COLORS in InitiativeDetail.tsx (backlog #9aa0ae, unstarted #e5a13c, started #4f8ef7, completed #42c88a, cancelled #e5484d). Done caption = completed + cancelled (same rule as InitiativeProgressBar).
  • Header actions: Archive (POST /epics/:id/archive) toggles to Restore (POST /epics/:id/unarchive) when archived_at is set; Edit opens the name/description dialog (PATCH); Delete asks for force when issue_count > 0 (server 409 ErrEpicHasIssues unless ?force=true).
  • Member issues: GET /epics/:epicID/issues. Attach = POST /epics/:epicID/issues {issue_ids} (idempotent, never 409 — mirror AddModuleIssues); detach = DELETE /epics/:epicID/issues. Only this project’s live issues are attachable. Attach/detach writes issue_activities (epic_added/epic_removed).
  • Linked initiatives: GET/POST/DELETE /initiatives/:initiativeID/epics (mirror initiative-project linking). Cross-scope read: the picker lists workspace initiatives.

Surface 3 — Issue detail: attach-epic control. Contract:
  • Issue detail carries epics: [{id, name, archived_at}]. Archived epics stay visible on the issue — the UI renders them dimmed (55% opacity, dashed border, archive icon) per the C71T0 contract. Removing a chip = DELETE /epics/:epicID/issues (writes epic_removed activity).
  • The picker lists active project epics only (archived hidden — the list call has no ?include_archived=true here). Selecting attaches via POST /epics/:epicID/issues {issue_ids: [issueId]}; attaching an already-attached epic is a no-op (idempotent add, never 409). Picker placement: issue Properties panel, mirroring the existing Modules picker cell.
  • An issue may carry multiple epics; chips wrap. The picker shows per-epic issue_count as the secondary line.
